# Ten-repository review for Gavin's Ghost Recorder

Research date: 2026-10-26. These are primary GitHub source observations, pinned to inspected commits. No source code, datasets, network services, multi-user models or outside defaults were imported. All five proposed changes retain one owner's local data, explicit ON/OFF recording and the existing menu workflow. An idea can have several references; repositories do not each imply a PR.

1. **[Hammerspoon/hammerspoon](https://github.com/Hammerspoon/hammerspoon)** — MIT. Inspected [event tap](https://github.com/Hammerspoon/hammerspoon/blob/23e387e2805a9890066366e0ac96c71b27f0cfd5/extensions/eventtap/libeventtap.m) and [event properties](https://github.com/Hammerspoon/hammerspoon/blob/23e387e2805a9890066366e0ac96c71b27f0cfd5/extensions/eventtap/libeventtap_event.m). It uses native session event taps and exposes event-source PID/user data. Application: keep capture responsive and offer an explicit offline source-PID exclusion for Gavin's chosen automation. PID is a hint, not authenticated physical-input provenance.
2. **[keycastr/keycastr](https://github.com/keycastr/keycastr)** — BSD-3-Clause. Inspected [tap implementation](https://github.com/keycastr/keycastr/blob/1e552a150afdf8f73fa4a12ba3cca1bbf09eb6ab/keycastr/KCEventTap.m) and [keystroke conversion](https://github.com/keycastr/keycastr/blob/1e552a150afdf8f73fa4a12ba3cca1bbf09eb6ab/keycastr/KCKeystroke.m). It separates key/mouse handling and rendered key interpretation. Application: preserve the selected personal input source rather than interpreting a virtual key code as a universal character. It is a visualizer, not a training pipeline.
3. **[ActivityWatch/aw-watcher-input](https://github.com/ActivityWatch/aw-watcher-input)** — GitHub did not identify a license in the inspected metadata; no copying is authorized by this review. [Watcher source](https://github.com/ActivityWatch/aw-watcher-input/blob/4e6461dbf55a1c1aa8f9ece4df5f109188f56f61/src/aw_watcher_input/main.py) aggregates keyboard/mouse activity into timed events. Application: preserve raw events while deriving selected summaries separately; the aggregated watcher cannot supply hold-time pairs. This reinforces keeping Gavin's original logs intact when applying offline exclusions/recovery.
4. **[ActivityWatch/aw-watcher-window](https://github.com/ActivityWatch/aw-watcher-window)** — MPL-2.0. [macOS implementation](https://github.com/ActivityWatch/aw-watcher-window/blob/10638b2c94e46195f709abd8626cb15f911e99f8/aw_watcher_window/macos.swift) combines focus notifications, polling, Accessibility lookups and a bounded ordered sender. Application: isolate window-title work from high-rate input ingestion, retain bounded outstanding work and reject stale results. This is an engineering adaptation; that project is not evidence this recorder's context is atomic.
5. **[pqrs-org/Karabiner-Elements](https://github.com/pqrs-org/Karabiner-Elements)** — repository metadata identifies Unlicense; vendored components have their own notices. [Input-source properties](https://github.com/pqrs-org/Karabiner-Elements/blob/91f928068243b4e9a1978ec36a9254fe1b71a549/vendor/vendor/include/pqrs/osx/input_source/properties.hpp) retain input-source identifiers as optional properties. Application: record Gavin's actual selected layout/IME with key events and mark a timing boundary when it changes. No remapping, virtual driver or universal keyboard model is added.
6. **[OpenAdaptAI/openadapt-capture](https://github.com/OpenAdaptAI/openadapt-capture)** — MIT; the repository announces migration to OpenAdapt's monorepo. [Recorder source](https://github.com/OpenAdaptAI/openadapt-capture/blob/6e2e1ad6e882a99b6e6e742a85cb812aee82c59f/openadapt_capture/recorder.py) separates producers/writers and associates action positions with published geometry. Application: keep display geometry attached to training context and preserve source evidence during interrupted-file handling. Its screenshot/audio/accessibility-tree scope is not added to Ghost Recorder.
7. **[humblebanana/open-record-replay](https://github.com/humblebanana/open-record-replay)** — MIT. [Recording contract](https://github.com/humblebanana/open-record-replay/blob/8eff3fa6217810a809b4f1e32ff5273416d36d63/docs/recording-data-contract.md) makes session boundaries and events.jsonl primary evidence and validates recordings before downstream use. Application: opt-in recovery of only a final interrupted JSON line, report the loss and invalidate pending holds. It does not establish that malformed interior lines can safely be ignored.
8. **[Aaru1801/TinyTask-macOS](https://github.com/Aaru1801/TinyTask-macOS)** — MIT. [Recorder source](https://github.com/Aaru1801/TinyTask-macOS/blob/8ccf3b4d19db88af5f0f01db7205f128fc116c0a/Sources/TinyRecorder/Recorder.swift) buffers high-frequency input and separates macro controls from recorded actions. Application: distinguish Gavin's own training sample from known automation/control input through explicit analysis selection. This is a derived idea, not a claim that TinyTask implements our PID filter. No replay feature is added.
9. **[spaansba/ForesightJS](https://github.com/spaansba/ForesightJS)** — MIT. [Mouse predictor](https://github.com/spaansba/ForesightJS/blob/f2aedc975ea3e4d755c908d612deda59bddf8b79/packages/js.foresight/src/predictors/MousePredictor.ts) uses recent pointer positions and element geometry for browser intent. Application: never pool the same absolute screen cell across different monitor geometry in Gavin's model. It predicts browser intent for known targets, not arbitrary desktop controls.
10. **[andyed/clicksense](https://github.com/andyed/clicksense)** — MIT. [Click collector](https://github.com/andyed/clicksense/blob/2daacb746cde45614725e3e65e945354b66f5b3d/src/clicksense.js) measures button duration and bounded approach motion, with a distinction between movement and pause. Application: preserve spatial context and chronology before interpreting Gavin's personal click habits. Cognitive-confidence interpretations are unvalidated project claims; they are not adopted.

## Five independent code ideas

- **Personal keyboard layout metadata:** record selected input-source ID/name at session start and changes; attach it to key events. Changes create a continuity boundary. Same personal settings, no forced keyboard layout.
- **Nonblocking window context:** run optional AX title reads away from the input run loop, bound outstanding queries and reject delayed replies after app/session/privacy changes.
- **Explicit automation exclusions in analysis:** repeatable source-PID selection filters only the owner's chosen software inputs, resets incomplete sequences and preserves original logs. Defaults retain all data.
- **Interrupted-tail recovery:** an explicit offline recovery flag may discard only an incomplete final JSON line and must report a gap. Interior corruption remains an error; source logs are never rewritten.
- **Display-specific personal click learning:** derive deterministic geometry contexts from the existing display metadata and train/evaluate each context separately, preserving original event coordinates. No other person's data or pretrained model is introduced.

These are implementation choices inferred from the cited designs. They do not establish hardware timing accuracy, semantic target recognition or next-click accuracy. Personal models/reports remain outside Git. No live recorder or permissions are enabled by this review.
